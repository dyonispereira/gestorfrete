## `modelos_ia`

Múltiplos modelos ativos simultaneamente é o esperado (D169), nunca uma exceção.

```sql
CREATE TYPE modelos_ia_tipo_enum AS ENUM ('CLASSIFICACAO', 'PREDICAO', 'OTIMIZACAO', 'VISAO_COMPUTACIONAL', 'GERACAO_DE_TEXTO');
CREATE TYPE modelos_ia_fornecedor_logico_enum AS ENUM ('INTERNO', 'PROVEDOR_EXTERNO');   -- D170 — nunca o nome do provedor real
CREATE TYPE modelos_ia_status_enum AS ENUM ('EM_TREINAMENTO', 'ATIVO', 'DESCONTINUADO');

CREATE TABLE modelos_ia (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id           UUID REFERENCES tenants(id),   -- nulo quando modelo padrão da plataforma
    nome                TEXT NOT NULL,
    tipo                modelos_ia_tipo_enum NOT NULL,
    versao              TEXT NOT NULL,
    fornecedor_logico    modelos_ia_fornecedor_logico_enum NOT NULL,
    capacidade           TEXT NOT NULL,
    contexto_maximo       INTEGER,
    status                modelos_ia_status_enum NOT NULL DEFAULT 'EM_TREINAMENTO',

    CONSTRAINT uq_modelos_ia_nome_versao UNIQUE (nome, versao)
);
```

## `inferencias_ia`

Mesmo padrão de observabilidade já usado em `eventos_fiscais` (Lote 9): entrada, saída, duração
(`GENERATED`), custo, modelo, status, confiança, timestamps.

```sql
CREATE TYPE inferencias_ia_origem_enum AS ENUM ('AUTOMATICO', 'MANUAL');
CREATE TYPE inferencias_ia_status_enum AS ENUM ('SUCESSO', 'FALHA', 'TIMEOUT');

CREATE TABLE inferencias_ia (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id           UUID NOT NULL REFERENCES tenants(id),
    modelo_ia_id         UUID NOT NULL REFERENCES modelos_ia(id),
    modelo_ia_versao     TEXT NOT NULL,   -- cópia fixa (D166/D169), nunca recalculada se o modelo evoluir
    entrada              JSONB NOT NULL,   -- ou referência a storage quando volumosa (D107)
    saida                JSONB,
    nivel_confianca       NUMERIC(5,2),    -- D168 — sempre estatístico, nunca certeza
    data_hora_inicio      TIMESTAMPTZ NOT NULL,
    data_hora_fim          TIMESTAMPTZ,
    duracao_ms             INTEGER GENERATED ALWAYS AS (
                               EXTRACT(EPOCH FROM (data_hora_fim - data_hora_inicio)) * 1000
                           ) STORED,
    custo                  NUMERIC(10,4),   -- ausente para modelo interno sem custo variável
    numero_tentativa        INTEGER NOT NULL DEFAULT 1,
    origem                  inferencias_ia_origem_enum NOT NULL,
    status                  inferencias_ia_status_enum NOT NULL DEFAULT 'SUCESSO'
)
PARTITION BY RANGE (data_hora_inicio);   -- D201 — "Alto" volume (HIGH_VOLUME_ENTITIES.md), mesmo
-- padrão de eventos_fiscais/execucoes_job (log técnico de execução), particionamento ausente por
-- descuido até esta correção

CREATE TABLE inferencias_ia_2026_01 PARTITION OF inferencias_ia
    FOR VALUES FROM ('2026-01-01') TO ('2026-02-01');

CREATE INDEX idx_inferencias_ia_modelo_id_criado_em ON inferencias_ia (modelo_ia_id, data_hora_inicio DESC);
CREATE INDEX idx_inferencias_ia_status ON inferencias_ia (tenant_id, status);
```

## `sugestoes_ia`

Recomendação, justificativa, confiança e decisão humana — colunas distintas, nunca misturadas.

```sql
CREATE TYPE sugestoes_ia_status_enum AS ENUM ('PENDENTE', 'ACEITA', 'REJEITADA', 'IGNORADA', 'EXPIRADA');

CREATE TABLE sugestoes_ia (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id           UUID NOT NULL REFERENCES tenants(id),
    inferencia_ia_id     UUID NOT NULL REFERENCES inferencias_ia(id),
    categoria            TEXT NOT NULL,   -- vocabulário extensível (D120)
    entidade_alvo_tipo    TEXT NOT NULL,
    entidade_alvo_id      UUID NOT NULL,
    recomendacao          TEXT NOT NULL,
    justificativa          TEXT NOT NULL,
    nivel_confianca         NUMERIC(5,2) NOT NULL,
    status                  sugestoes_ia_status_enum NOT NULL DEFAULT 'PENDENTE',
    usuario_decisao_id       UUID REFERENCES usuarios(id),
    data_hora_decisao        TIMESTAMPTZ
);

CREATE INDEX idx_sugestoes_ia_entidade_alvo ON sugestoes_ia (entidade_alvo_tipo, entidade_alvo_id);
CREATE INDEX idx_sugestoes_ia_status ON sugestoes_ia (tenant_id, status);
CREATE INDEX idx_sugestoes_ia_usuario_decisao_id ON sugestoes_ia (usuario_decisao_id);
```

## `predicoes_ia`

Só a previsão — nunca o resultado real (isso é `Feedback de IA.resultado_real`, D192).

```sql

    valor_previsto             NUMERIC(12,4) NOT NULL,
    nivel_confianca             NUMERIC(5,2) NOT NULL,
```

## `leituras_visao_computacional`

```sql
CREATE TYPE leituras_visao_computacional_tipo_enum AS ENUM ('CANHOTO', 'AVARIA', 'MARCA_DE_FOGO', 'IMPLEMENTO');
CREATE TYPE leituras_visao_computacional_status_enum AS ENUM ('PROCESSADA', 'CONFIRMADA', 'REJEITADA');

CREATE TABLE leituras_visao_computacional (
    id                              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id                       UUID NOT NULL REFERENCES tenants(id),
    inferencia_ia_id                 UUID NOT NULL REFERENCES inferencias_ia(id),
    arquivo_origem_id                 UUID NOT NULL,   -- D107 — nunca blob
    tipo_leitura                      leituras_visao_computacional_tipo_enum NOT NULL,
    regiao_analisada                   JSONB,
    resultado_extraido                  JSONB NOT NULL,   -- sempre proposta, nunca aplicado automaticamente (D161)
    nivel_confianca                     NUMERIC(5,2) NOT NULL,
    revisao_humana_necessaria            BOOLEAN NOT NULL DEFAULT FALSE,
    status                               leituras_visao_computacional_status_enum NOT NULL DEFAULT 'PROCESSADA',
    usuario_confirmacao_id                UUID REFERENCES usuarios(id),

    CONSTRAINT ck_leituras_visao_computacional_confirmacao_humana
        CHECK (
            status = 'PROCESSADA'
            OR revisao_humana_necessaria = FALSE
            OR usuario_confirmacao_id IS NOT NULL
        )
        -- toda saída CONFIRMADA/REJEITADA que exigia revisão humana precisa de um usuário — D161/D164
);
```

## Índices — resumo (temporais e de decisão, como esperado neste domínio)

| Tabela | Índice |

| `sugestoes_ia` | `(entidade_alvo_tipo, entidade_alvo_id)`, `(tenant_id, status)`, `(usuario_decisao_id)` |
| `predicoes_ia` | `(entidade_alvo_tipo, entidade_alvo_id)`, `(status, data_hora_validade_fim)` |
| `classificacoes_ia` | `(entidade_alvo_tipo, entidade_alvo_id, tipo_classificacao)` |
| `anomalias_detectadas` | `(leitura_origem_tipo, leitura_origem_id)` |
| `feedbacks_ia` | `(saida_ia_tipo, saida_ia_id)` |

`nivel_confianca` não recebeu índice próprio — não é usada como filtro de igualdade/intervalo em
consulta operacional conhecida hoje (é exibida, não filtrada); adicionar quando um caso de uso real
exigir (ex: "todas as sugestões com confiança abaixo de X"), não preventivamente.

## Constraint de confirmação humana (pedido explícito)

Já implementada em `leituras_visao_computacional` (`ck_leituras_visao_computacional_confirmacao_humana`,
acima) — o mesmo padrão se aplicaria a qualquer futura saída de IA que ganhe um fluxo de
confirmação obrigatória, sempre a mesma forma: `status` terminal só é alcançável com
`usuario_*_id` preenchido quando `revisao_humana_necessaria` (ou equivalente) for verdadeiro.

## Observabilidade — mesmo padrão de Evento Fiscal/Rastreamento/Sincronização

`inferencias_ia` já reúne todos os campos sugeridos (`data_hora_inicio`/`fim`, `duracao_ms`,
`status`, `numero_tentativa`, `custo`, `origem`) — não repetidos aqui. `correlation_id` **não**
adicionado nesta rodada: nenhuma tabela de IA ainda encadeia múltiplas inferências numa mesma
transação de negócio (diferente de `logs_auditoria.id_correlacao`, que agrupa efeitos em vários
bounded contexts de uma única ação) — adicionar agora seria antecipar um caso de uso ainda não
existente; fica registrado como extensão natural quando um fluxo de IA multi-etapa surgir.
