# 011 — BI

Entidades da camada analítica do GestorFrete. Template completo de 22 campos (ver
[`README.md`](./README.md)).

## Princípio fundamental (D149): BI não é dono de nenhum dado operacional

Duas categorias de dado, nunca confundidas:

| | Operational Data | Analytical Data |
|---|---|---|
| Exemplos | Viagem, Abastecimento, Ordem de Serviço, CT-e, MDF-e | Ranking, Indicadores, Tendências, Séries históricas, Comparativos, KPIs, Dashboards |
| Dono | O bounded context operacional (`freight`, `maintenance`, `documents`, ...) | `analytics`/`reporting` |
| Quem escreve | O próprio bounded context, via suas regras de negócio | `analytics`/`reporting`, lendo (nunca escrevendo) os dados operacionais |
| Mutabilidade | Segue a máquina de estados/histórico de cada entidade | Consolidada e, uma vez fechada (Snapshot Analítico), imutável (D151) |

`analytics`/`reporting` **nunca** altera uma Viagem, um Abastecimento, uma Ordem de Serviço ou
qualquer outra entidade operacional (D149) — só lê, via evento (D008) ou consulta, e produz suas
próprias entidades derivadas. Isso é a aplicação mais explícita até agora de D090 (indicadores nunca
são atributos operacionais): agora existe um bounded context inteiro dedicado a onde esses
indicadores de fato vivem.

## Métrica

- **Objetivo**: Fórmula reutilizável e catalogada (ex: "Média KM/L", "Receita por KM", "Receita por
  Veículo", "Disponibilidade", "OTIF", "Margem", "ROI da Frota") — é, ao mesmo tempo, o "Catálogo de
  Indicadores" pedido: um catálogo de Métricas **é** o catálogo de indicadores.
- **Responsabilidades**: Declarar fórmula, origem (quais entidades/campos de quais bounded contexts
  alimentam o cálculo) e versão (D150) — permite que centenas de KPIs existam sem lógica duplicada,
  e que qualquer resultado histórico seja auditável/reproduzível.
- **O que não faz**: Não calcula nada sozinha — é a definição; `Indicador Consolidado` é o resultado
  de aplicá-la. Não altera dado operacional (D149).
- **Aggregate Root**: Sim — entidade de **Referência** (D036), catálogo.
- **Bounded Context proprietário**: `analytics`
- **Principais relacionamentos**: Indicador Consolidado (1:N — cada resultado aplica uma Métrica);
  Cubo Analítico (referenciada, quando a métrica é uma medida do cubo).
- **Eventos que publica**: `MetricaCadastrada`, `MetricaVersionada` (novos).
- **Eventos que consome**: Nenhum.
- **Invariantes**: nome único por tenant (ou Platform Reference Data, D046, quando a métrica é
  padrão da plataforma, disponível a todos os tenants); **nova versão da fórmula nunca sobrescreve a
  anterior (D155)** — gera uma nova versão, preservando o histórico de cálculo dos indicadores já
  gerados com a versão antiga (D150).
- **Regras de negócio associadas**: D090 (indicadores nunca são atributos operacionais — aqui é onde
  de fato vivem), D149, D150, D155.
- **Estados**: `Ativa` / `Descontinuada`.
- **Auditoria**: D007 — alteração de fórmula é sensível (afeta todos os KPIs que a usam).
- **Linha do tempo**: cadastro, versionamento.
- **Anexos suportados**: Não aplicável.
- **Comentários suportados**: Sim, documentação da fórmula para outros analistas (D023).
- **KPIs relacionados**: Não aplicável — ela é a definição, não o resultado.
- **Documentos canônicos relacionados**: Nenhum ainda.
- **Evoluções futuras previstas**: editor visual de fórmulas para usuários avançados do tenant.
- **Dependências obrigatórias**: Nenhuma.
- **Dependências proibidas**: Nenhuma restrição de leitura (por natureza, pode referenciar campos de
  qualquer bounded context em sua fórmula, sempre como leitura, D008) — mas nunca escreve em nenhum.
- **Dono da Timeline**: Aggregate Métrica (este próprio).
- **Capacidade Offline**: Consulta Offline.

## Indicador Consolidado

- **Objetivo**: O resultado calculado de aplicar uma Métrica a uma granularidade e período
  específicos — o "KPI" propriamente dito.
- **Responsabilidades**: Guardar o valor já calculado, pronto para consulta rápida por Dashboards,
  sem recalcular a fórmula a cada exibição.
- **O que não faz**: **Nunca é editável diretamente (D090)** — só existe via recálculo da Métrica que
  o originou; **nunca contém a fórmula em si (D156)** — apenas referencia qual Métrica e qual versão
  dela foi usada; não altera dado operacional (D149).
- **Aggregate Root**: Sim — entidade **Histórica** por natureza (um novo período gera um novo
  registro, nunca sobrescreve o anterior).
- **Bounded Context proprietário**: `analytics`
- **Principais relacionamentos**: Métrica (N:1); entidade-dimensão (referência polimórfica —
  Viagem/Veículo/Motorista/Cliente/Tenant, conforme a granularidade dimensional, D153).
- **Eventos que publica**: `IndicadorRecalculado` (novo).
- **Eventos que consome**: Todo evento relevante dos bounded contexts operacionais que a Métrica
  associada declara como origem (D008, D032).
- **Invariantes**: sempre associado a exatamente uma Métrica, um período e uma dimensão — nunca um
  valor "solto" sem se saber a que nível ele se refere (D153).
- **Regras de negócio associadas**: D090, D149, D153 (granularidade explícita: temporal —
  diário/semanal/mensal; dimensional — por Viagem/Veículo/Motorista/Cliente), D156.
- **Estados**: Não aplicável — é ele próprio o valor calculado.
- **Auditoria**: D007 — de quando o recálculo ocorreu, não de "quem alterou" (ninguém altera
  diretamente).
- **Linha do tempo**: Não aplicável — é ele mesmo um valor de série temporal.
- **Anexos suportados**: Não aplicável.
- **Comentários suportados**: Não aplicável.
- **KPIs relacionados**: Ele mesmo é o KPI.
- **Documentos canônicos relacionados**: Nenhum ainda.
- **Evoluções futuras previstas**: recálculo incremental (Bloco Agendamento de Atualização, abaixo).
- **Dependências obrigatórias**: Métrica.
- **Dependências proibidas**: Nenhuma restrição de leitura; nunca escreve em bounded context
  operacional algum (D149).
- **Dono da Timeline**: Não aplicável.
- **Capacidade Offline**: Consulta Offline.

## Snapshot Analítico

- **Objetivo**: O fechamento consolidado e **imutável** de um período (ex: Resultado Mensal) — a
  peça mais importante deste documento, por pedido explícito.
- **Responsabilidades**: Preservar o resultado de um período fechado mesmo que os dados operacionais
  de origem mudem depois (ex: uma Viagem antiga corrigida não altera retroativamente o Resultado
  Mensal já fechado).
- **O que não faz**: Não se atualiza automaticamente após consolidado (D151) — uma correção
  necessária gera um novo Snapshot/ajuste explícito, referenciando o original, nunca uma reescrita.
- **Aggregate Root**: Sim — entidade **Histórica** (D037), imutável por definição (D151).
- **Bounded Context proprietário**: `analytics`
- **Principais relacionamentos**: Múltiplos Indicadores Consolidados (N:N — um Snapshot agrega vários
  KPIs do período fechado).
- **Eventos que publica**: `SnapshotAnaliticoConsolidado` (novo).
- **Eventos que consome**: Nenhum diretamente — é acionado por Agendamento de Atualização ou ação
  manual de fechamento.
- **Invariantes**: uma vez `Consolidado`, nenhum valor dentro do snapshot muda — nunca, sob nenhuma
  circunstância (D151, reforço máximo, mesmo nível de rigor de `Log de Auditoria`, D147/D109);
  **sempre informa sua própria origem (D160)** — quais Métricas participaram, o período consolidado
  e a versão de cada Métrica usada, nunca um fechamento "opaco".
- **Regras de negócio associadas**: D037, D038 (mesmo princípio de Snapshot Histórico da Viagem,
  aplicado aqui a um fechamento de período inteiro, não a um único atributo), D100 (imutável), D151,
  D160.
- **Estados**: `Em Aberto` / `Consolidado`.
- **Auditoria**: D007 — quem/quando consolidou.
- **Linha do tempo**: abertura do período, consolidação.
- **Anexos suportados**: relatório PDF gerado no fechamento (D024/D107, referência a `storage`).
- **Comentários suportados**: Sim, notas do fechamento (D023).
- **KPIs relacionados**: Contém os Indicadores Consolidados do período, mas não os recalcula depois
  de `Consolidado`.
- **Documentos canônicos relacionados**: Nenhum ainda.
- **Evoluções futuras previstas**: fechamento automático agendado (Agendamento de Atualização,
  abaixo) com aprovação humana antes de `Consolidado`.
- **Dependências obrigatórias**: Ao menos um Indicador Consolidado.
- **Dependências proibidas**: Nunca escreve em bounded context operacional (D149).
- **Dono da Timeline**: Aggregate Snapshot Analítico (este próprio).
- **Capacidade Offline**: Consulta Offline.

## Cubo Analítico

- **Objetivo**: Preparação para consultas multidimensionais futuras (OLAP-style) — define quais
  dimensões (Tempo, Veículo, Motorista, Cliente, Filial) e quais medidas (Métricas) compõem um cubo
  de análise, sem ainda implementar o motor de consulta em si.
- **Responsabilidades**: Ser a definição/metadado de um cubo — quais dimensões, quais medidas, qual
  granularidade mínima.
- **O que não faz**: Não armazena os dados do cubo em si nesta fundação — é a definição estrutural;
  a materialização (motor OLAP, armazenamento colunar) é decisão de infraestrutura futura, fora do
  escopo deste domínio.
- **Aggregate Root**: Sim — entidade de **Referência** (D036).
- **Bounded Context proprietário**: `analytics`
- **Principais relacionamentos**: Métrica (N:N — medidas do cubo).
- **Eventos que publica**: `CuboAnaliticoDefinido` (novo).
- **Eventos que consome**: Nenhum.
- **Invariantes**: nome único por tenant; ao menos uma dimensão e uma medida.
- **Regras de negócio associadas**: D049/D050 (preparação para alto volume/consulta analítica).
- **Estados**: `Ativo` / `Inativo`.
- **Auditoria**: D007.
- **Linha do tempo**: definição, alterações de estrutura.
- **Anexos suportados**: Não aplicável.
- **Comentários suportados**: Não crítico, mas suportado (D023).
- **KPIs relacionados**: Nenhum direto — é estrutura, não resultado.
- **Documentos canônicos relacionados**: Nenhum ainda.
- **Evoluções futuras previstas**: motor de consulta multidimensional real (ex: engine OLAP
  dedicado) — esta entidade é só a preparação estrutural, por pedido explícito desta rodada.
- **Dependências obrigatórias**: Ao menos uma Métrica.
- **Dependências proibidas**: Nunca escreve em bounded context operacional (D149).
- **Dono da Timeline**: Aggregate Cubo Analítico (este próprio).
- **Capacidade Offline**: Consulta Offline.

## Dashboard Personalizado

- **Objetivo**: Uma tela configurável de visualização de indicadores — guarda **apenas
  configuração**, nunca dado (D152).
- **Responsabilidades**: Guardar layout, quais widgets exibir, filtros aplicados, preferências do
  usuário que o criou.
- **O que não faz**: **Nunca armazena o valor de nenhum indicador** (D152) — ao ser renderizado,
  busca os dados ao vivo de `Indicador Consolidado`/`Snapshot Analítico`. Isso é o que garante D154:
  o Dashboard é inteiramente reconstruível a partir dos bounded contexts oficiais, porque ele mesmo
  não guarda nada além de "como exibir". Por D158, um mesmo Dashboard pode combinar widgets de
  Métricas/Indicadores originados de bounded contexts operacionais diferentes simultaneamente (ex:
  um widget de Custo de Manutenção ao lado de um de Receita) — nunca limitado a uma única origem.
- **Aggregate Root**: Sim.
- **Bounded Context proprietário**: `reporting`
- **Principais relacionamentos**: Usuário (N:1, dono); Widget (composição — cada widget referencia
  uma Métrica/Indicador Consolidado, nunca copia o valor, podendo cada widget vir de uma Métrica de
  bounded context diferente, D158); Filtro Favorito (referenciado, opcional).
- **Eventos que publica**: `DashboardPersonalizadoCriado`, `DashboardPersonalizadoAtualizado`
  (novos).
- **Eventos que consome**: Nenhum.
- **Invariantes**: nome único por Usuário; nunca persiste um valor numérico de indicador dentro de
  sua própria estrutura (D152/D154).
- **Regras de negócio associadas**: D149, D152, D154.
- **Estados**: `Ativo` / `Arquivado`.
- **Auditoria**: D007.
- **Linha do tempo**: criação, alterações de layout.
- **Anexos suportados**: Não aplicável.
- **Comentários suportados**: Não aplicável.
- **KPIs relacionados**: Referencia KPIs, não é um.
- **Documentos canônicos relacionados**: Nenhum ainda.
- **Evoluções futuras previstas**: compartilhamento de dashboard entre usuários/perfis.
- **Dependências obrigatórias**: Usuário.
- **Dependências proibidas**: Nunca guarda dado operacional nem valor de indicador já resolvido
  (D152) — apenas a referência de como buscá-lo.
- **Dono da Timeline**: Aggregate Dashboard Personalizado (este próprio).
- **Capacidade Offline**: Consulta Offline (o layout pode ser consultado offline; os dados exibidos
  exigem conexão para busca ao vivo).

## Relatório Salvo

- **Objetivo**: Uma definição de relatório reutilizável (quais Métricas/Indicadores, filtros,
  formato de saída) — distinto de Dashboard por ser orientado a geração pontual/agendada de
  documento, não a uma tela interativa.
- **Responsabilidades**: Guardar a definição do relatório; ser a origem de Exportações Geradas.
- **O que não faz**: Não guarda o conteúdo do relatório em si — apenas a definição; o conteúdo
  gerado é sempre uma Exportação Gerada nova.
- **Aggregate Root**: Sim.
- **Bounded Context proprietário**: `reporting`
- **Principais relacionamentos**: Usuário (N:1, dono); Métrica/Indicador Consolidado (referenciados,
  N:N); Exportação Gerada (1:N).
- **Eventos que publica**: `RelatorioSalvoCriado` (novo).
- **Eventos que consome**: Nenhum.
- **Invariantes**: nome único por Usuário.
- **Regras de negócio associadas**: D149, D152-style.
- **Estados**: `Ativo` / `Arquivado`.
- **Auditoria**: D007.
- **Linha do tempo**: criação, execuções (por referência a Exportação Gerada).
- **Anexos suportados**: Não aplicável (a própria definição não tem anexo — o resultado sim, via
  Exportação Gerada).
- **Comentários suportados**: Não crítico, mas suportado (D023).
- **KPIs relacionados**: Referencia KPIs, não é um.
- **Documentos canônicos relacionados**: Nenhum ainda.
- **Evoluções futuras previstas**: agendamento de envio automático por e-mail (via Agendamento de
  Atualização, abaixo).
- **Dependências obrigatórias**: Usuário.
- **Dependências proibidas**: Nunca guarda dado operacional resolvido.
- **Dono da Timeline**: Aggregate Relatório Salvo (este próprio).
- **Capacidade Offline**: Consulta Offline (a definição; a geração exige conexão).

## Exportação Gerada

- **Objetivo**: O arquivo de fato gerado a partir de um Relatório Salvo ou de um Dashboard exportado
  (PDF/Excel/CSV).
- **Responsabilidades**: Guardar referência ao arquivo gerado (D107 — nunca o binário inline), o
  momento da geração e o **contexto completo que a originou (D157)**: filtros utilizados, período,
  usuário solicitante e versão de cada Métrica envolvida — para que qualquer exportação passada seja
  auditável e reproduzível.
- **O que não faz**: Não é editável — cada exportação é um novo registro/arquivo, nunca uma
  atualização (D037/D123-style, reforço a qualquer artefato gerado).
- **Aggregate Root**: Sim — entidade **Histórica** (D037).
- **Bounded Context proprietário**: `reporting`
- **Principais relacionamentos**: Relatório Salvo (N:1, opcional — pode ser exportação avulsa de um
  Dashboard); Usuário (N:1, quem solicitou).
- **Eventos que publica**: `ExportacaoGerada` (novo).
- **Eventos que consome**: Nenhum.
- **Invariantes**: arquivo sempre referenciado por `storage` (D107); contexto de geração sempre
  completo (D157) — nunca uma exportação sem filtros/período/usuário/versão registrados.
- **Regras de negócio associadas**: D107, D037, D157.
- **Estados**: `Processando` / `Concluída` / `Falhou`.
- **Auditoria**: D007.
- **Linha do tempo**: solicitação, conclusão.
- **Anexos suportados**: o próprio arquivo gerado (Arquivo, D024/D107).
- **Comentários suportados**: Não aplicável.
- **KPIs relacionados**: Nenhum direto.
- **Documentos canônicos relacionados**: Nenhum ainda.
- **Evoluções futuras previstas**: envio automático por e-mail/webhook ao concluir.
- **Dependências obrigatórias**: Nenhuma obrigatória (Relatório Salvo é opcional).
- **Dependências proibidas**: Nunca escreve em bounded context operacional.
- **Dono da Timeline**: Aggregate Relatório Salvo, quando originada de um; senão, própria.
- **Capacidade Offline**: Não.

## Agendamento de Atualização

- **Objetivo**: Define como e quando um Indicador Consolidado, Snapshot Analítico ou Cubo Analítico
  é recalculado — tempo real, incremental, diário ou manual.
- **Responsabilidades**: Ser consultado pelo processo de recálculo (job assíncrono, ver `Execução de
  Job`, [`010-administracao.md`](./010-administracao.md)) para decidir a frequência.
- **O que não faz**: **Nunca executa cálculo algum (D159)** — apenas solicita a atualização,
  disparando uma `Execução de Job`; quem de fato calcula continua sendo exclusivamente `analytics`.
- **Aggregate Root**: Sim.
- **Bounded Context proprietário**: `reporting`
- **Principais relacionamentos**: Métrica/Cubo Analítico (referência polimórfica — o que está sendo
  agendado).
- **Eventos que publica**: `AgendamentoDeAtualizacaoDefinido` (novo).
- **Eventos que consome**: Nenhum.
- **Invariantes**: exatamente um modo de atualização por alvo.
- **Regras de negócio associadas**: D149, D159.
- **Estados**: `Ativo` / `Inativo`.
- **Auditoria**: D007.
- **Linha do tempo**: definição, alterações.
- **Anexos suportados**: Não aplicável.
- **Comentários suportados**: Não aplicável.
- **KPIs relacionados**: Nenhum direto.
- **Documentos canônicos relacionados**: `010-administracao.md` (Execução de Job).
- **Evoluções futuras previstas**: atualização adaptativa (mais frequente em horário de pico
  operacional).
- **Dependências obrigatórias**: Métrica ou Cubo Analítico.
- **Dependências proibidas**: Nunca escreve em bounded context operacional.
- **Dono da Timeline**: Aggregate Agendamento de Atualização (este próprio).
- **Capacidade Offline**: Consulta Offline.
